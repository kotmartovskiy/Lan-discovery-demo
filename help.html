1. Обзор проекта

Веб-панель управления домашней инфраструктурой на базе X96 Max (Armbian OS 26.11.0 bookworm, hostname armbian). Единое приложение (Flask + SQLite) для мониторинга сети, устройств, погоды, валют, управления мультимедией, встроенных утилит и игр.

Технологии

  • Сервер: Python 3 + Flask (порт 8090)
  • База данных: SQLite (/opt/lan-discovery/devices.db)
  • Сканирование сети: nmap (ARP-сканирование)
  • Погода: Open-Meteo API (57.0°N, 41.0°E)
  • Валюты: CoinGecko + Frankfurter + Yahoo Finance
  • Модули: вкл/выкл разделов, установка зависимостей — страница «Модули»
  • Системный сервис: lan-discovery.service (systemd)

8. API (JSON)

Полный и поддерживаемый каталог эндпоинтов — документация docs/API.md в репозитории проекта (та же копия — в публичном Lan-discovery-docs). Ручная копия каталога в справке больше не ведётся: она расходилась с кодом.

Опорные эндпоинты: GET /api/status — общий статус; GET /api/dashboard — агрегат для шапки (система/здоровье/устройства/события); GET /api/health — версия/аптайм/бэкапы. Авторизация — сессионная cookie, mutation-запросы требуют CSRF-токен (заголовок X-CSRFToken).

Резервные копии

Бэкапы хранятся рядом с исходными файлами и в /srv/backup-db (системный раздел SD). Рекомендации:

  • Перед любым изменением app.py — бэкап: cp /opt/lan-discovery/app.py /opt/lan-discovery/app.py.backup-$(date +%Y%m%d-%H%M%S)
  • Бэкап БД вручную: cp /opt/lan-discovery/devices.db /opt/lan-discovery/devices.db.backup-$(date +%Y%m%d-%H%M%S)
  • Восстановление — из файлов .backup-* или через страницу «Система»

10. Решение проблем

Панель не открывается

  • Проверьте статус: systemctl status lan-discovery
  • Посмотрите логи: journalctl -u lan-discovery -n 50
  • Проверьте порт: ss -tlnp | grep 8080
  • Перезапустите: systemctl restart lan-discovery

Устройства не обнаруживаются

  • Убедитесь что устройства в одной подсети (192.168.1.0/24)
  • Проверьте nmap: nmap -sn -PR 192.168.1.0/24
  • Убедитесь что ARP-сканирование не блокируется файрволом

Погода не обновляется

  • Кэш погоды — 15–30 минут, обновляется при обращении к странице/шапке
  • Проверьте доступность API: curl "https://api.open-meteo.com/v1/forecast?latitude=57.0&longitude=41.0¤t_weather=true"
  • Посмотрите логи панели: journalctl -u lan-discovery -n 50

Бэкап БД не создаётся

  • Вручную: cp /opt/lan-discovery/devices.db /opt/lan-discovery/devices.db.backup-$(date +%Y%m%d-%H%M%S)
  • Проверьте место: df -h /
  • Бэкап со страницы «Система» пишет в /srv/backup-db

Ошибка синтаксиса Python

  • Проверка: python3 -c "import py_compile; py_compile.compile('opt/lan-discovery/app.py', doraise=True)"
  • Восстановление из бэкапа: cp /opt/lan-discovery/app.py.backup-XXXXXX /opt/lan-discovery/app.py

Клонирование не запускается

  • Клонирование eMMC → SD отключено, пока система загружена с SD-карты — dd перезаписал бы работающую систему (на этой панели система: /dev/mmcblk1p2, SD)
  • Если система загружена с eMMC: нажмите «Проверить SD» и убедитесь, что разделы SD не смонтированы: umount /dev/mmcblk1*
  • eMMC = /dev/mmcblk2

11. FAQ

Как добавить IPTV-плейлист?

На странице «Система» → блок «IPTV» → введите URL m3u-файла → нажмите «Добавить».

Как добавить веб-камеру?

На странице «Система» или в разделе «Мультимедиа» → введите URL потока (RTSP/HTTP) → нажмите «Добавить».

Как добавить онлайн-радио?

В разделе «Приложения» → Radio → введите URL потока и название станции → «Добавить».

Как пользоваться калькулятором?

Откройте вкладку «Приложения» → Калькулятор. Переключайтесь между обычным и инженерным режимами кнопкой.

Как работает генератор паролей?

Откройте «Приложения» → Пароли → настройте длину и типы символов → нажмите «Сгенерировать». Пароли хранятся в зашифрованном виде.

Как добавить тестовый адрес для проверки сети?

На странице «Система» → блок «Сеть» → нажмите «Изменить» рядом с нужным адресом.

Как сделать полный backup системы?

Файловые бэкапы создаются вручную (см. раздел 9, «Резервные копии»), БД — через страницу «Система» или cp. Образ SD можно сделать утилитой dd на другой диск.

Как восстановить систему из backup?

Восстановление файлов — из .backup-* рядом с файлами; БД — через страницу «Система» («Восстановить БД»). Аварийный доступ — restore-server.service (порт 8081).

Как подключиться к серверу по SSH?

ssh root@192.168.1.243 (пароль — от root-аккаунта; не храните его в открытом виде). Рекомендуется настроить SSH-ключи для безопасности.

Как перезагрузить сервер через веб-панель?

Страница «Система» → «Управление питанием» → «Перезагрузить». Подтвердите действие.

Как выключить сервер?

Страница «Система» → «Управление питанием» → «Выключить питание». После команды можно отключить кабель питания.

Где хранятся данные torrent-клиента?

/srv/downloads/ — загруженные файлы (системный раздел SD); конфигурация Transmission — в /etc/transmission-daemon/.

Как обновить панель?

Отредактируйте /opt/lan-discovery/app.py, затем: systemctl restart lan-discovery. Перед изменением обязательно сделайте бэкап!

Как играть в Змейку?

Откройте «Приложения» → Змейка. Управление: клавиши WASD или стрелки.

Как работает секундомер?

Откройте «Приложения» → Секундомер. Нажмите «Старт» для запуска, «Круг» для фиксации промежуточного времени, «Стоп» для остановки.

📦 Bluetooth

Где это: плитка «Bluetooth» на /apps (оверлей).

  • Статус адаптера (MAC, имя, вкл/выкл), видимость, поиск и подключение устройств (колонки, гарнитуры), управление парами.
  • API: GET /api/bluetooth/status|devices|paired|discovered, POST /api/bluetooth/scan|power|connect|disconnect|pair|remove|discoverable|trust.
  • Статус читается из /sys/class/bluetooth, управление — через bluetoothctl.
  • Зависимости модуля: пакет bluez (apt), сервис bluetooth.
  • Выключенный модуль: плитка скрыта, /apps/bluetooth и /api/bluetooth → 404.

📦 DLNA

Где это: плитка «DLNA» на /apps (оверлей).

  • Выключенный модуль: плитка скрыта, /apps/dlna и /api/dlna → 404.

📦 Мониторинг

Где это: вкладка «Мониторинг».

  • Хост помечен ONLINE/OFFLINE; клик по строке — детальные графики Netdata.
  • Страница: агрегация данных по хостам в реальном времени, аккордеон по хостам, прогресс-бары с цветовой индикацией (норма / предупреждение / критично).
  • API: GET /api/monitoring/<ip> — метрики хоста (503, если хост недоступен).
  • Зависимости модуля: пакет netdata (apt), сервис netdata. Чтобы хост был виден извне: bind socket to IP = 0.0.0.0 в /etc/netdata/netdata.conf.

📦 Торренты

Где это: вкладка «Торрент» в верхнем меню.

  • Веб-интерфейс Transmission v4 встроен прямо во вкладку (порт 9091).
  • Скачанные файлы: /srv/downloads (общий шары также видны в Samba/DLNA).
  • Входящие соединения: TCP/UDP 51413.
  • RPC без пароля — только для локальной сети; из интернета порт не открывать.

Сервис и конфиг:

  • systemctl status transmission-daemon — состояние.
  • /etc/transmission-daemon/settings.json — настройки; после правки: systemctl restart transmission-daemon.

Очередь и управление — через API панели: /api/transmission/queue, /api/transmission/action, /api/transmission/add.

Зависимости модуля: transmission-daemon (apt), сервис transmission-daemon, папка /srv/downloads — ставятся кнопкой «Установить зависимости» на странице «Модули».

Если вкладка выключена: страница и API /torrent, /api/transmission отвечают 404, пункт меню скрыт. Включить обратно можно на странице «Модули» (админ).

📦 Погода

Где это: вкладка «Погода» + краткий статус в шапке панели.

  • Локация: Иваново (57.0°N, 41.0°E), часовой пояс Europe/Moscow, источник — Open-Meteo API.
  • Карточки: температура, «ощущается как», ветер, влажность, давление, UV-индекс, видимость, восход/закат.
  • Прогноз: почасовой + на 5 дней, история за 24 часа, радиационный фон (мкЗв/ч), качество воздуха AQI.
  • Выходные дни в таблице прогноза подсвечены красным.
  • Обновление данных каждые 30 минут; кэш API-ответов — 15 минут.
  • UV-индекс: шкала 0–11+ с цветовыми зонами и рекомендациями по защите от ультрафиолета.
  • Радиационный фон: единицы мкЗв/ч, статусы Normal / Warning / Danger, норма 0.05–0.1 мкЗв/ч; источники — данные МЧС и radiationweather.com (карта уровня радиации).
  • Качество воздуха AQI: шкала 0–500, параметры PM2.5, PM10, CO, NO₂ с рекомендациями по здоровью.
  • «Пульс сервера»: latency (задержка ответа), CPU, RAM, disk, uptime.
  • Статус обновления в шапке: GET /api/weather-status (элемент #weather-status).
  • Кэширование ответов ~15–30 минут; при недоступности API показываются последние данные.
  • Зависимости модуля: нет (Open-Meteo API, пакеты не нужны).
  • Выключенный модуль: вкладка скрыта, /weather и /api/weather* → 404.
